# Инструкция по бессерверному развертыванию на Vercel («Вставил и всё»)

Настоящая инструкция описывает резервный и полностью бесплатный способ развертывания системы **«Пульс Доступа»** на платформе **Vercel** в качестве полноценной альтернативы Docker-контейнерам.

---

## ⚡ Преимущества Vercel перед Docker на VPS

1. **Не нужен арендованный сервер / VPS**: Vercel предоставляет бесплатный тариф Hobby Tier с автоматическим глобальным CDN и SSL-сертификатом.
2. **Нулевое обслуживание**: Нет необходимости настраивать Linux, Docker, Supervisor, следить за памятью или обновлять пакеты ОС.
3. **Бесшовный резерв (Failover)**: Если ваш основной VPS или Docker-контейнер временно недоступен — сервис разворачивается на Vercel менее чем за 60 секунд.
4. **Общая база данных**: Vercel использует ту же самую облачную базу **Google Cloud Firestore** и репозиторий **GitVerse**, поэтому подписчики, боты и персональные файлы подписок сохраняются и не дублируются.

---

## 🚀 Быстрый запуск в 4 шага

### Шаг 1. Импорт проекта в Vercel
1. Зарегистрируйтесь или войдите на [vercel.com](https://vercel.com) (можно войти через GitHub/GitLab).
2. Нажмите **«Add New...»** → **«Project»**.
3. Выберите ваш репозиторий с проектом и нажмите кнопку **«Import»**.
4. В разделе **«Build and Output Settings»**:
   - **Framework Preset**: `Vite` или `Other` (определяется автоматически благодаря `vercel.json`).
   - **Build Command**: `vite build` (по умолчанию).
   - **Output Directory**: `dist` (по умолчанию).

---

### Шаг 2. Добавление переменных окружения (Environment Variables)
В панели управления «Пульс Доступа» перейдите во вкладку:
👉 **Настройки** → **Vercel & Бессерверный перенос** и нажмите фиолетовую кнопку:

> **«Скопировать все переменные для Vercel в 1 клик»**

Затем в Vercel Dashboard раскройте секцию **«Environment Variables»**:
- Кликните в поле ввода первого ключа (Key) и нажмите **Ctrl+V** (или Cmd+V).
- Vercel автоматически распознает все строки и заполнит ключи и значения!

#### Список используемых переменных:
| Переменная | Описание | Обязательность |
| :--- | :--- | :--- |
| `NODE_ENV` | `production` — максимальное быстродействие | Обязательно |
| `VERCEL` | `1` — флаг бессерверного окружения | Обязательно |
| `PORT` | `3000` — внутренний порт | Рекомендуется |
| `GITVERSE_TOKEN` | Токен OpenAPI GitVerse для записи файлов подписок | Обязательно |
| `GITVERSE_OWNER` | Владелец репозитория (например, `Vaynet`) | Обязательно |
| `GITVERSE_REPO` | Имя репозитория (например, `bot`) | Обязательно |
| `TELEGRAM_BOT_TOKEN` | Токен активного бота из BotFather | Обязательно |
| `FIREBASE_API_KEY` | Ключ доступа к Cloud Firestore | Обязательно |
| `FIREBASE_PROJECT_ID` | Идентификатор проекта Firestore | Обязательно |
| `FIREBASE_DATABASE_ID` | Идентификатор базы данных Firestore | Обязательно |

---

### Шаг 3. Деплой приложения
1. Нажмите кнопку **«Deploy»**.
2. Дождитесь завершения сборки (обычно 25–45 секунд).
3. Vercel предоставит адрес развернутого приложения, например:
   `https://my-puls-app.vercel.app`

---

### Шаг 4. Активация Telegram Webhook
Так как в Serverless функции не могут постоянно опрашивать Telegram в фоновом цикле (Long-Polling), Telegram должен сам доставлять события через Webhook.

1. Откройте вкладку **«Vercel & Бессерверный перенос»** в панели управления.
2. Вставьте ваш полученный адрес Vercel (например, `https://my-puls-app.vercel.app`).
3. Нажмите кнопку **«🚀 Установить Webhook на Vercel»**.
4. Готово! Система вызовет `Telegram API setWebhook`, и бот начнет моментально отвечать на команды `/start`, проверять каналы и выдавать конфигурации клиентам HAPP и INCY.

## 🔄 Как переключаться между Vercel и Docker без конфликтов

Вы можете легко использовать любой из двух способов или держать Vercel как горячий резерв:

* **Переключение на Vercel**: 
  Нажмите кнопку *«Установить Webhook на Vercel»*. Telegram переключится на отправку событий по URL.
* **Возврат на Docker / VPS**: 
  Нажмите кнопку *«Сбросить Webhook»*. Telegram вернется в режим стандартного Long-Polling, и Docker-контейнер продолжит опрос в штатном режиме.

## 🗄️ База данных на Vercel: Firebase Cloud ⇄ Нативная база Vercel KV

Проект поддерживает **полную гибкость работы с данными**. Вы можете:
1. **Использовать существующую Firebase Firestore** (по умолчанию, общий банк данных с Docker).
2. **Переподключить проект к местной бессерверной базе данных Vercel (Vercel KV / Upstash Redis)**.
3. **Запустить гибридный режим (Dual-Write)** — одновременная запись в обе базы без риска потери данных.
4. **В 1 клик перенести (мигрировать)** всех подписчиков, ботов, правила и файлы между Firebase и Vercel KV туда и обратно.

---

### Вариант А. Работа через общую Firebase Cloud Firestore (по умолчанию)
- **Как работает**: При копировании блока `.env` для Vercel в проект автоматически попадают ключи `FIREBASE_API_KEY`, `FIREBASE_PROJECT_ID`, `FIREBASE_DATABASE_ID`.
- **Преимущество**: Нулевая настройка. Все данные синхронно доступны и в Docker, и на Vercel. Если вы добавили подписчика на Vercel — он сразу отобразится на основном сервере.

---

### Вариант Б. Подключение местной / встроенной базы данных Vercel (Vercel KV)
У Vercel есть нативный сервис быстрых бессерверных баз данных **Vercel KV** (на базе высокопроизводительного Upstash Redis):
1. В панели [vercel.com](https://vercel.com) откройте ваш проект.
2. Перейдите во вкладку **Storage** в верхнем меню.
3. Нажмите кнопку **«Create Database»** и выберите **«KV»** (Upstash Redis).
4. Задайте имя (например, `puls-kv`) и регион (например, Франкфурт `fra1` или Вашингтон `iad1`).
5. Нажмите **«Create»**. Vercel автоматически добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` в ваш проект!
6. В панели управления «Пульс Доступа» в разделе **«База данных»** выберите:
   - **Активный бэкенд**: `Vercel KV (Native Redis)`
   - Нажмите **«Тест связи Vercel KV»** — система проверит отклик (обычно 5–15 мс)
   - Нажмите **«Применить конфигурацию БД»**.

---

### 🔄 Мастер двусторонней миграции данных
В панели управления «Пульс Доступа» во вкладке **«Vercel & Бессерверный перенос»** доступны кнопки мгновенной миграции:

1. **«Firebase ➔ Vercel KV»**:
   - Автоматически считывает всех существующих пользователей, токены ботов, репозитории GitVerse и списки исключений из Firebase.
   - Записывает их в нативное хранилище Vercel KV.
   - Проверяет обратное контрольное чтение и подтверждает успешный перенос.

2. **«Vercel KV ➔ Firebase»**:
   - Считывает актуальное состояние из базы Vercel KV и реплицирует его обратно в Cloud Firestore.
   - Позволяет в любой момент вернуться с Vercel обратно на Docker или использовать обе системы.

3. **«Скачать JSON-дамп»** и **«Восстановить из JSON»**:
   - Позволяет сохранить полную резервную копию всей базы данных на свой компьютер в виде одного `.json` файла и при необходимости восстановить её в один клик.

---

### 🛡️ Вариант В. Гибридный режим (Dual-Write Репликация)
При включении чекбокса **«Включить фоновую параллельную репликацию (Dual-Write)»** сервис будет:
- Читать данные с максимальной скоростью из выбранного основного бэкенда.
- При любом изменении (регистрация пользователя, привязка устройства, продление подписки, выпуск ключа) сохранять данные **одновременно и в Firebase, и в Vercel KV**.
- Это обеспечивает абсолютную отказоустойчивость: если одна из облачных систем временно недоступна, вторая моментально обеспечивает непрерывную раздачу подписок HAPP и INCY.

## 🛠 Конфигурационный файл vercel.json
Файл `vercel.json` уже включен в корень репозитория:
```json
{
  "version": 2,
  "buildCommand": "vite build",
  "outputDirectory": "dist",
  "functions": {
    "api/index.ts": {
      "maxDuration": 30,
      "memory": 1024
    }
  },
  "rewrites": [
    {
      "source": "/api/(.*)",
      "destination": "/api"
    },
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

## 🔍 Проверка и диагностика работы
На странице **«Vercel & Бессерверный перенос»** доступен встроенный диагностический инструмент:
1. Введите URL развернутого проекта.
2. Нажмите **«Проверить отклик API»**.
3. Система замерит задержку (ping в миллисекундах) и проверит доступность эндпоинта `/api/status`, состояние базы пользователей и синхронизацию с GitVerse.
